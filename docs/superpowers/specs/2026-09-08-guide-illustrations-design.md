# 使い方案内を図で見せる

作成日: 2026-09-08

## 背景

使い方の案内が文字だけで、一番つまずく「貼る」がテキスト3行でしか説明されていない。

- `HowToSendViewController` は SF Symbols のアイコン＋テキストの3行
- `UsageViewController` も同じ作り
- `TopViewController` には抽象的なグラデの星型の絵があるだけで、何をするアプリか絵から分からない

App Store 入稿画像（`一時素材/appstore/final_1.png` 〜 `final_6.png`）には同じ3ステップの図解が既にある。ただしこれは 2.0.0 時点の見た目で、文言が画像に焼き込まれており、直近のタイトル2行化で現物とずれた。ストア画像をそのままアプリへ持ち込むと、この「ズレ」を仕様として抱えることになる。

## 決まっていること

検討の過程で以下を確定した。

| 論点 | 決定 |
|---|---|
| 図に何を写すか | 自分たちのUIに加え、②③もトーク画面を模したモックを描く。他社アプリのロゴ・固有の意匠は使わない |
| 画像として焼くか画面上で組むか | **画面上で組む**（UIKitのライブビュー）。撮影・生成パイプラインは作らない |
| ①のキーボードの再現度 | 簡略化した図として組む。キーボード拡張のターゲットには触らない |
| 図に出す画像 | 利用者の保存画像を最大3枚。足りないぶんは見本画像で埋める |
| 対象画面 | `HowToSend` と `Top`。`Usage` は今回触らない |
| Top への差し込み方 | Storyboard に容器の `UIView` を1つ足し、中身はコードで組む |

### 画面上で組む理由

②③はどのみちこちらでモックを作ることになる。作ったモックを撮って画像にするくらいなら、撮らずにそのまま画面へ置けばよい。加えて、

- ロケール別のアセット生成が要らない。文言は `Localizable.strings` から出る
- ダークモードと Dynamic Type に自動で追従する。焼いた画像だけが枠の外の異物になる
- アプリ容量が増えない（PNGだと ステップ3 × ロケール2 × テーマ2 × 3倍解像度 の掛け算になる）
- 「現物とのズレ防止」という要件が、設計の時点で消える

### アプリ本体に置く理由

案内図はアプリ側だけの機能。`PhotoKeyboardFramework` はメモリ上限の厳しいキーボード拡張もリンクするため、拡張が使わないコードを入れる理由がない。マイボードのセル（`PhotoKeyboardEx/PhotoCollectionViewCell.swift`）も同じ判断でアプリ側に置かれている。

デザイントークンは framework 側で既に `public` かつダークモード対応で、`keyboardBase` / `keyboardSurface`（キーボードの地の色）も揃っている。図はこれらをそのまま使い、独自の色を足さない。

## 構成

`PhotoKeyboardEx/Guide/` に新規作成する。

### GuideKeyboardStripView

ステップ①「キーボードで画像をタップ」の図。

- `.keyboardBase` の地に、角丸のサムネイルを横3枚
- 先頭の1枚に「コピー」バッジを重ねる
- サムネイルは `RealmPhoto.thumbnail(maxPixelSize:)` から取る。フル解像度をデコードしない

### GuideComposerView

ステップ②「入力欄を長押しして『ペースト』」の図。

- `Radius.small` の角丸で入力欄のバーを描く
- その上に「ペースト」の吹き出しを1つ。吹き出しの文言は `Localizable.strings` から取る

### GuideChatView

ステップ③「そのまま送信」の図。

- 相手の吹き出しを1つ、こちらが送った画像を1枚
- 時刻・既読・アイコンは**入れない**。他社アプリの意匠に寄りすぎるため

### GuideStepView

番号バッジ、文言、図をひとつに積む器。

- 番号バッジ（1/2/3）
- 既存の文言をそのまま使う。太字と通常文の連結、日英の語順出し分け（`Lang.langRootKey()`）は現行の `makeStepRow` の実装を移す
- 図は上記3つのいずれかを受け取る

### GuidePhotoSource

図に流し込む画像を決める。

- `RealmManager.shared.realmData` のうち `isUserOwned` が真のものを、ボードに並ぶ順で先頭から最大3枚
- 3枚に満たないぶんは見本画像（`officialPhotoWelcome` アセット）で埋める
- 見本を除外して数えるのは、埋める側と埋められる側が混ざらないようにするため。`realmData` には見本が常に含まれるので、素朴に先頭3枚を取ると「利用者の画像が0枚」という状態を表現できない
- 新規利用者は自分の画像が0枚なので、スロットは見本3枚（同じ絵が3つ）になる。決定済みの挙動だが、実物を見て違和感があれば調整する

## 各画面の変更

### HowToSendViewController

`makeStepRow(symbol:bold:normal:)` を `GuideStepView` に差し替える。

- 手順の文言のキー（`howToFirstBoldText` 等）は変更しない。既存の文言をそのまま使う
- SF Symbol のアイコン（`Symbol.stepTap` 等）は図に置き換わるため、この画面では使わなくなる
- スクロールビュー・閉じるボタン・`howToSendDone()` の記録は現行のまま

### TopViewController / Top.storyboard

星型の絵は残し、その下に図をひとつ足す。

- `Top.storyboard` に容器の `UIView` を1つ追加し、`@IBOutlet` で受ける
- 中身（タップ→貼るの図）はコードで組み、容器に敷く
- ロゴのアニメーション（`heightConstraint` / `leftConstraint` を直接いじる）には触らない

**既知のリスク**: Top は既にヒーロー画像＋見出し＋サブタイトル＋ボタン＋規約文で埋まっている。図を足すと小さい端末（SE）で縦が溢れる可能性が高い。実機とシミュレータで確認し、溢れるならスクロール化する。この判断は実装時に実測してから行う。

## テスト

`PhotoKeyboardExTests` に追加する。

見た目は**描画結果のピクセルで検証**する。直近のタイトル2行化で、`textRect(forBounds:limitedToNumberOfLines:)` が折り返しの有無を反映せず「画面は1行なのにテストは2行と答える」状態を通してしまった。同じ轍を踏まない。

| 検証 | 内容 |
|---|---|
| 図が描かれること | 各ステップの図をレイアウトし、インクのある画素が存在すること |
| 画像の補填 | 保存画像が0枚・1枚・2枚のとき、スロットが3つ埋まること |
| 画像の優先 | 保存画像が3枚以上あるとき、見本で埋めないこと |
| Dynamic Type | 最大の文字サイズで図が器からはみ出さないこと |
| ダークモード | 図と地のコントラストが確保されること（既存の色コントラストテストに倣う） |

## やらないこと

- `Usage`（キーボード有効化の案内）は触らない
- アニメーションはしない
- 撮影・画像生成のパイプラインは作らない
- キーボード拡張のターゲット（`PhotoKeyboardExOrigin`）には一切触らない

`Localizable.strings` への追加は、②の吹き出しに出す「ペースト」の1語だけに限る。手順の文言はすべて既存キーを使う。
